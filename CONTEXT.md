# CONTEXT.md — Domain Context & ADRs

## Domain Glossary

| Term | Definition |
| --- | --- |
| **Research Hub** | The clinical research blog reader module (`blog.html`) displaying curated emergency medicine and clinical informatics articles. |
| **Toxico** | The clinical toxicology reference sub-app and project card link. |
| **papers.json** | Automated file holding the top 12 emergency medicine papers, parsed daily via n8n. |
| **latest_updates.json** | Ephemeral JSON file pushed from Notion to trigger GitHub Actions build, deduplicated and chunked. |
| **blog_index.json** | Autogenerated list of chunk paths (`data/blog/research_chunk_*.json`), read by the processing script. |
| **Post index** | `data/blog/index.json`: one compact row per post (title, date, PMID, chunk, specialty, study design, tags). The only file the reader needs to draw its list. |
| **Specialty** | One of a fixed list of clinical areas assigned to a post at build time from its tags (multi-label, up to 3). |
| **Study design** | One of a fixed list of design groups (Randomized trial, Cohort study, ...) read from the `Study Design:` line of the AI summary; absent when the summary does not state one. |
| **Paper ledger** | The homepage list of `papers.json`, grouped by curation date. |
| **pl (Knowledge Vault)** | Scoped sub-app displaying private knowledge vault markdown files merged at build time. |

## Ubiquitous Language

- **Paper/Post**: A single curated clinical research entry containing metadata, objective, methods, results, and clinical relevance commentary.
- **Tags**: The three free-form AI keyword tags stored with each post. Shown on the paper and searchable, but not used as filters.
- **Topics**: The two build-time facets used for filtering: Specialty and Study design.
- **Drawer Overlay**: The slide-out menu layout designed for mobile screen widths containing search and filter controls.
- **Deduplication Map**: Dual-layer filtering (Notion ID primary, PMID secondary) preventing duplicate paper records.

## Architectural Decision Records (ADRs)

### ADR-001: Notion-to-GitHub Static Publishing

- **Context**: A database was needed to hold summaries of research papers, but keeping a live server running would incur costs and maintenance overhead.
- **Decision**: Use Notion as the CMS. An n8n workflow queries Notion database and pushes changes to GitHub. A GitHub Action parses, deduplicates, and splits the data into static JSON chunks (`data/blog/*.json`) that are fetched on demand.
- **Consequence**: Zero-cost, high-performance static hosting on GitHub Pages, with simple client-side page rendering.

### ADR-002: Service Worker Cache (Offline-First)

- **Context**: As a clinical reader app used by an ER Physician, network connectivity inside hospitals can be highly unstable.
- **Decision**: Implement a Service Worker (`sw.js`) with cache-first static caches and network-first dynamic caches, separated by version.
- **Consequence**: Core files and previously read articles remain fully readable without active internet connection. Offline page requests fallback to path-appropriate directory index caches (e.g. `/blog.html`) instead of blindly routing to `/index.html`.

### ADR-003: Mobile Drawer UX for Blog Reader

- **Context**: The original layout stacked the sidebar above the reading view on mobile viewports. With extensive filter tags, the header took up all the space, pushing the paper list completely out of view and leaving very little room for article reading.
- **Decision**: Replaced the stacked mobile layout with a slide-out drawer overlay (`position: fixed`) and backdrop overlay, auto-closing upon paper selection. Forced tags to stay in a single horizontally scrollable row.
- **Consequence**: Restores full screen height for reading, eliminates overlapping bugs, and provides a native-like mobile app experience.

### ADR-004: CSS Modularization & Theme Centralization

- **Context**: Inline style blocks grew up to 1,000 lines within single HTML files, causing huge codebase redundancy, hard-to-maintain theme styling, and slow cache performance.
- **Decision**: Centralize all light/dark mode variables and global rules in `shared.css`. Extract page-specific inline styles into external stylesheets (`index.css` and `blog.css`). Refactor sub-page stylesheets to inherit variables from `shared.css`.
- **Consequence**: Improves code readability, maintainability, and reusability. External stylesheets are cached by the browser and service worker, reducing page load times and network overhead.

### ADR-005: Braun-Era Paper-Industrial Theme Migration

- **Context**: The existing blue-accented glassmorphic and shadow-heavy design was generic and distracted from the medical content. A unique, premium, distraction-free clinical reader aesthetic was desired.
- **Decision**: Migrate to a paper-industrial theme inspired by 1960s-70s Braun product design (Dieter Rams). Adopt a warm cream/paper background (`#ebe7df`) and near-black text (`#1a1a1a`) with a deep navy nav gradient. Contrast this in dark mode using inverted colors (deep navy background with light cream text). Reduce card radius to a harder industrial edge (`4px`/`2px`), flatten shadows, remove modern transition lifts, and restrict signal orange (`#d84315`) to high-priority items.
- **Consequence**: Establishes a highly distinct, professional, clinical "printed document" design system with strong typography (`Inter Tight`, `Sarabun`) and excellent readability under unstable hospital lighting conditions.

### ADR-006: Navigation Bar Contrast and Card Hover Refinements

- **Context**: The initial navigation bar implementation in Light Theme fallback colors made brand headings illegible on its dark navy background. Additionally, the border styles on action buttons inside the nav looked cluttered, and project cards lacked clear interactive feedback compared to the clean layout used in other components.
- **Decision**: Locked the header brand text to warm off-white (`#F0EDE5`) and ivory (`#c4bfb0`) across both themes. Removed borders from action buttons to emphasize a flat, solid, matte UI. Applied the "minimal standout" sentinel design from the Standing Order Hub to homepage project cards (`#49628d` background and a `4px` left border sentinel `#F0EDE5` on hover, offset by padding), and implemented smooth CSS transitions (0.2s ease) on child elements (`.project-title`, `.project-desc`, `.project-icon`) to prevent abrupt visual snapping.
- **Consequence**: Restores perfect contrast readability on the sticky nav header and aligns the portfolio card list with the core design principles of flat, responsive, and tactile interactive responses with smooth, premium transitions.

### ADR-007: Responsive Nav Right-Alignment and Header Color Standardization

- **Context**: Mobile navigation menus on sub-pages were disorganized, utilizing varied alignments (some stretched, some left-aligned, some right-aligned). Additionally, on the blog page, the mobile drawer collapsed state was broken on initial load because the sidebar lacked default hidden positions and the menu button was invisible/non-interactive on mobile viewports.
- **Decision**: Set the mobile layout of navigation controls to `justify-content: flex-end; gap: 12px;` to neatly right-align buttons on mobile screens. Forced the `blog.html` sidebar to collapse dynamically on mobile load, modified the mobile CSS to transition the sidebar based on `.collapsed`, and overrode the mobile open button opacity and pointer-events to ensure visibility.
- **Consequence**: Delivers a fully cohesive, consistent header navigation experience across all sub-apps, solves mobile drawer access, and aligns with the responsive, premium design guidelines.

### ADR-008: PWA Meta Sync, Caching Preflight & Telemetry Stability

- **Context**: Sub-pages needed consistent `<meta name="theme-color">` tags and unified PWA Service Worker (`sw.js`) registration. Favicons were using an outdated bright blue color.
- **Decision**: Synchronized the theme-color meta tag and SVGs (to match the Rams navy gradient and cream palette) globally across all sub-pages. Registered the Service Worker in all entrypoints.
- **Consequence**: Ensures robust offline loading and PWA support across all core pages.

### ADR-009: Jekyll Build Document Exclusions

- **Context**: Internal documents (`ARCHITECTURE.md`, `CONTEXT.md`, `DESIGN.md`, `Braun-theme.md`, `README.md`) contain private architectural diagrams, system specifications, and sensitive design mappings. When Jekyll runs, it copies these files by default into the `_site/` directory, exposing them as public raw text files.
- **Decision**: Introduce a `_config.yml` at the repository root containing an `exclude` list that covers these core documentation files at the root level, and also within the private `pl/` subdirectory checkout directory.
- **Consequence**: Prevent accidental public exposure of raw internal design, logic, and workflow context, ensuring those remain strictly confidential. Exclusions are defined with literal file names (`pl/tree.json` and `pl/external_links.json`) to prevent syntax ambiguity in the Jekyll compiler.

### ADR-010: Default to Latest Paper in Blog Reader

- **Context**: When visiting the research blog reader directly, the reader pane was left empty, displaying a placeholder telling the user to select a paper. This required an extra click and felt incomplete on initial landing.
- **Decision**: Update the client-side router (`handleRouting`) and history navigation (`onpopstate`) to automatically select and load the first paper (`filteredPosts[0]`) in the sorted list if no specific ID query parameter is present or found.
- **Consequence**: Provides a seamless clinical reading experience from the first interaction, automatically highlighting the selected sidebar list item, and ensuring consistent rendering during browser history back/forward navigation.

### ADR-011: Decommissioning of Package Tracking Dashboard

- **Context**: The package tracking dashboard and its automated background polling were decommissioned to streamline repository scope and focus exclusively on clinical informatics, research curation, and medical tools.
- **Decision**: Completely removed the tracking dashboard (`tracking/`), polling scripts (`tracker.py`), and background cron workflows (`track-packages.yml`).
- **Consequence**: Reduced repository attack surface, simplified service worker caching rules, and eliminated extraneous GitHub Actions cron executions.

### ADR-012: Dedicated Bottom Footer Link Anchor and Threshold-Gated Drag Interactions

- **Context**: On the homepage, paper cards needed an intuitive interaction model where text selection and horizontal dragging on the card body do not trigger unintended navigation, while clicking the dedicated footer section below the divider line reliably opens the paper.
- **Decision**: Keep `.paper-card` as a `<div>` list item container, and structure the bottom section below the divider line (`.paper-link`) as the dedicated `<a>` anchor spanning the entire bottom area of the card. Remove the aggressive `pointer-events: none` CSS suppression rule. Gate drag-state activation strictly to movements exceeding 5px on left-click (`e.button === 0`), and cleanly intercept/cancel click propagation only when an actual drag occurred.
- **Consequence**: Clicking or highlighting text on the card body (date, title, comment) does not trigger navigation, while clicking anywhere in the comfortable footer zone under the divider line opens the publication in a new tab. Horizontal mouse drag scrolling continues to work smoothly without accidental clicks.

### ADR-013: Tactile Card Hover, SVG Iconography & Anti-Slop Refinement

- **Context**: Light theme card hover inverted the entire card background to deep navy (`#1E3A6D`), creating visual flash and jarring contrast. Furthermore, raw emojis scattered across UI elements clashed with the serious clinical systems identity, and carousel controls overflowed container boundaries.
- **Decision**: Calibrate Light theme hover tokens (`--card-hover-bg: #F8F8FA`) with tactile elevation (`transform: translateY(-2px)`), soft shadow (`var(--shadow-hover)`), and crisp border highlight (`#1E3C72`), eliminating full-card navy flipping. Replace all raw emojis with 1.5px/2.0px stroke vector SVGs, eliminate em-dashes across markup and styles, and integrate carousel controls into the section header.
- **Consequence**: Delivers a calm, publication-grade Dieter Rams / Apple Slate experience with tactile micro-interactions and zero AI-slop tells.

### ADR-014: Fixed Taxonomy Replaces Free-Form Tag Filters

- **Context**: 1,460 posts carried 1,119 distinct AI tags, 783 of them used once. The filter showed 12 pills and a "More" list of over 1,100 entries; client-side normalization covered ten spellings. The two largest tags ("Emergency Medicine", "Emergency") matched almost everything.
- **Decision**: Assign each post, at build time, to a fixed list of 18 specialties (multi-label, from tags first, title as fallback; corpus-wide tags ignored) and one of 9 study-design groups (from the `Study Design:` summary line). Rules live in `.github/scripts/taxonomy.js`. The reader filters on these two facets; raw tags remain visible and searchable. `?tag=` links are read as a search. Supersedes the Tag Filtering rules of the earlier architecture.
- **Consequence**: 98% of posts land in at least one specialty; about a third have no stated design (older summaries lack the line) and match no design filter. Renaming or adding a category is one edit plus `--reindex`. New entries must be appended, since the index stores positions.

### ADR-015: Index-First Loading and Append-Only Chunks

- **Context**: The reader downloaded every chunk (3.8 MB) on each visit with a `Date.now()` cache-buster, then wrote the whole set to `localStorage` (2.2 M characters, at Safari's quota; an over-quota write threw inside the load path and showed "Failed to load data"). Chunks were re-sorted newest-first on every run, so each daily commit rewrote all eight files; `.git` had reached 83 MB.
- **Decision**: `process_blog.js` writes `data/blog/index.json` for the list and keeps chunks append-only (a post never moves; unchanged files are not rewritten). The reader loads the index and the chunk of the open paper, and the remaining chunks only for full-text search. The `localStorage` copy is removed; the service worker is the offline store. Requests revalidate with `cache: 'no-cache'` instead of query-string busters.
- **Consequence**: First load drops from about 3.8 MB to about 0.9 MB uncompressed (index + one chunk). A daily run changes one chunk and the index. Offline, a paper is readable if its chunk was fetched before. A post whose record is missing from its chunk (index and chunk out of step) shows an inline error with a retry.

### ADR-016: Substring Search With Ranking Replaces Subsequence Matching

- **Context**: `fuzzyMatch` accepted a query when its letters appeared in order anywhere in a ~900-character summary. "xylophone" returned 211 posts; "sepsis" returned 1,238 where 100 contain the word.
- **Decision**: Split the query into terms; every term must occur as a substring of the title, tags, PMID, specialty labels or summary. Rank title hits first, then tag hits, then summary-only hits; keep date order within a rank.
- **Consequence**: Results are explainable and typo-intolerant. Thai terms work, since matching is plain substring.

### ADR-017: Service Worker Limited to This Repo, Network-First, No Forced Reload

- **Context**: The worker at scope `/` answered every same-origin request cache-first, including sibling project sites such as `/er-hub/` and `/pl/`, which could therefore be served one version behind. Cache-busted data URLs each created a new cache entry. `skipWaiting()` plus a `controllerchange` reload reloaded the page on a first visit and mid-article. The offline fallback `caches.match(a) || caches.match(b)` never reached `b` (a Promise is always truthy).
- **Decision**: Handle only the shell and data files of this repository; pass everything else to the network. Use network-first with a 4-second timeout and cache fallback, keyed without the query string. Show a "Reload" bar when a new worker takes over a page that was already controlled; never reload automatically. Amends ADR-002.
- **Consequence**: Sibling tools are no longer cached by this worker (those needing offline use ship their own, as `/er-hub/` does). Online visitors get current code on the first load after a deploy.

### ADR-018: Paper Ledger Replaces the Homepage Carousel

- **Context**: The homepage showed 70 papers in a horizontally auto-scrolling carousel, three visible at a time, with drag inertia and pagination dots (ADR-012). Scanning it took dozens of interactions, and motion that starts by itself is hard to read under pressure.
- **Decision**: Render `papers.json` as a vertical list grouped by date; the title is the PubMed link, the Thai comment sits under it. Show the newest days first with a "Show all" control. Tools move beside the list on wide screens, grouped by a new `category` field; icons are chosen by an `icon` key instead of matching words in the title. Supersedes ADR-012 and the hover rules of ADR-013 for these two components.
- **Consequence**: Ten papers and the first tools are readable without interaction. Adding a tool no longer needs a code change. The carousel controls (`#slide-prev`, `#slide-next`, `#paper-indicators`) are gone.

### ADR-019: Editorial Masthead & Bento Tools Directory Replace Navy Topbar

- **Context**: While `blog.html` used a flat Slate/Titanium Navy surface from the top edge, `index.html` retained a full-bleed navy gradient topbar (`site-header on-navy`, ADR-006), creating a dated portal header and burying the primary `Open the research reader` CTA below 10 papers in the left column while squeezing 12 tools into a narrow 380px sidebar.
- **Decision**: Retire the navy gradient topbar and `--nav-*` tokens from `shared.css`, `index.html`, `index.css`, and `DESIGN.md` § 4.2. Replace `<header class="site-header on-navy">` with a flat editorial masthead directly on `--bg-body` anchored by a `1px solid var(--text-main)` hairline. Recompose `index.html` into two full-width sections: a sticky-rail split paper ledger (`#papers-section`) that brings `Open the research reader` and `Show all N papers` above the fold, followed by an asymmetric bento tools directory (`#works-section`) pairing `Clinical tools` against `Simulators` + `Research & statistics` with `Knowledge & notes` spanning three columns below.
- **Consequence**: `index.html` and `blog.html` now share one cohesive flat Slate/Titanium Navy aesthetic. Desktop visitors reach the research reader CTA immediately above the fold, and tool descriptions gain room to breathe; tools now begin below the 10-paper ledger on desktop instead of beside it.

### ADR-020: Balanced Horizontal Paged Paper Ledger with Dot Marks

- **Context**: The sticky left-rail split in `#papers-section` (ADR-019) left a tall empty column and pushed `Clinical Systems & Tools` below the `1440×900` fold. Meanwhile, `Research Blog` is already accessible from the masthead, so repeating `Open the research reader` and `Show all N papers` buttons in `#papers-section` was redundant when all 70 papers can be paged horizontally in place.
- **Decision**: Remove `Open the research reader` and `#papers-more` from `#papers-section`. Replace `.paper-ledger` with a native CSS `scroll-snap` horizontal track (`.paper-track`) chunked into 6-paper slides (2 columns × 3 rows at `≥860px`), navigated via touch/trackpad swipe, threshold-gated mouse drag (`> 5px`), keyboard arrows, and accessible dot-mark + previous/next `<button>` controls in `.section-header`. No auto-scroll (`DESIGN.md` § 1).
- **Consequence**: All 70 papers are browsable horizontally without growing page height; `Latest Research Papers` (~515px) and `Clinical Systems & Tools` (~578px) share comparable proportions and both appear above the `1440×900` fold.

### ADR-021: 4-Color Clinical Editorial Semantic Palette

- **Context**: While the Slate/Titanium Navy baseline delivered clean readability, relying on a single signal orange accent left tool categories, paper dates, and research specialties visually uniform and harder to scan at a glance.
- **Decision**: Introduce a 4-color Clinical Editorial Multi-Accent token system in `shared.css` (`--accent-navy`, `--accent-vermilion`, `--accent-teal`, `--accent-ochre`) with calibrated light/dark text (`>= 5.0:1`), mark/border, and soft icon-badge tint tokens bound via `[data-tone]`. Apply minimal semantic touches across `index` (section header bars, teal paper dates, vermilion active pager dot, per-category tool icon badges and top/hover sentinels) and `blog` (3-color reading progress bar, vermilion active item bar, tone-mapped specialty tags/labels, and color-coded summary section rails) while keeping all primary card/page surfaces neutral.
- **Consequence**: Adds clear visual hierarchy and rapid category scanning in both Light and Dark themes without sacrificing WCAG AA/AAA contrast or neutral background calm; bumped `sw.js` cache to `v7`.

### ADR-022: Unknown Paper Links Show a Notice; Legacy Duplicates Removed

- **Context**: A link carrying an `id` or `pmid` that matched no paper fell through to the default paper (ADR-010) with no sign that it was a different one, so a shared link could present the wrong paper as the one shared. Separately, four PMIDs were held twice (1,465 records): `mergeUpdates` blocks a new record whose PMID is already present, but nothing removed pairs written before that check.
- **Decision**: Keep the ADR-010 default, and show `#route-notice` above the paper when the link named one that is not held, linking to PubMed when a numeric PMID was given. Add `process_blog.js --dedupe`, which keeps the newest record per Notion ID and per PMID and removes the rest in place. Amends ADR-010.
- **Consequence**: 1,461 records, no repeated PMID. A removed Notion ID that n8n sends again is skipped by the existing PMID check. Old links to a removed record open the default paper under the notice.

### ADR-023: First-Seen Date and Stated AI Provenance

- **Context**: The only date stored per post was Notion's `property_last_edited_time` (`property_date` is empty in every record), so editing an old page re-dated it and moved it to the top of the reader, and the bare date read as a publication date. Summaries and homepage comments are written by an AI model, which the pages did not say.
- **Decision**: `mergeUpdates` stamps a new record with `first_seen` and carries it across updates; the index sorts on `first_seen`, falling back to the last-edited time for older records. The reader labels the date `Added <date>`. Both pages carry one `.ai-note` line naming the AI's role and telling the reader to check the original paper (`DESIGN.md` § 4.4).
- **Consequence**: Order is stable under Notion edits. Records written before this change gain `first_seen` the next time n8n resends them, taking their previous last-edited time. The publication date is still not stored.

### ADR-024: PNG App Icons, Bounded Fetch Wait, Service Worker v8

- **Context**: The manifest carried its icons as inline SVG `data:` URIs that draw the letter in whatever sans-serif the device has, and the pages had no `apple-touch-icon`, so iOS had no home-screen icon to use. `fetchWithFallback` had no time limit: with nothing cached, a stalled connection left a skeleton on screen indefinitely. Focusing the search box (or pressing `/`) downloaded every chunk before a character was typed. The worker still listed `blog_index.json`, which the reader stopped fetching (ADR-015), and a `CLEAR_CACHE` message handler nothing sends.
- **Decision**: Ship PNG icons in `assets/icons/` (192, 512, maskable variants, 180px apple-touch-icon) and drop the manifest's portrait lock. Abandon a fetch attempt that gets no response within 8 seconds; the limit is lifted once headers arrive, so a large chunk on a slow link is not restarted. Start the full-text load on the first typed character. Remove the dead worker entries, treat `/blog` as `/blog.html`, and bump the cache to `v8`. Remove four tokens no rule used (`--ink`, `--signal-ink`, `--primary-hover`, `--state-ok`).
- **Consequence**: Installed icons look the same on every device, and tablets can rotate the installed app. A dead connection reaches the retry button after two attempts (about 17 seconds). Fonts are still served by Google and are not available offline; self-hosting them is the remaining step.

### ADR-025: Self-Hosted Fonts

- **Context**: Both pages loaded three families through a render-blocking stylesheet on `fonts.googleapis.com`. The worker cached responses only when `response.ok`, and that cross-origin stylesheet arrives opaque, so it was never stored: offline, the font files were in the cache but no `@font-face` rule pointed at them, and every face fell back to a system font. On a stalled connection the same stylesheet held up first paint.
- **Decision**: Serve the fonts from this origin. Six woff2 subsets (Inter Tight variable 400 to 700 latin, JetBrains Mono 400 latin, Sarabun 400 and 600 in thai and latin; about 109 KB, SIL Open Font License) live in `assets/fonts/` with `@font-face` rules in `shared.css`. The worker precaches them and serves them cache-first from `ntwkkm-fonts-v2`; cache version `v9`. The primary UI face is preloaded. Completes the step ADR-024 left open.
- **Consequence**: Typography is identical online and offline, and no font request reaches a third party. Latin Extended, Cyrillic, Greek and Vietnamese subsets were not copied; a character outside Latin-1 and Thai falls back to the system font. Font updates are manual.

### ADR-026: Tests Gate the Deploy

- **Context**: The browser test only checked that no script threw, ran beside the deploy rather than before it, and installed an unpinned Puppeteer on every run. The reader's logic lived in `blog.js` next to DOM code, so none of it could be unit tested. The DESIGN.md rules on tokens and motion were checked only by a local tool.
- **Decision**: `pages-build-deployment.yml` calls `browser-test.yml` and builds only when it passes. That workflow runs the unit tests, a new `lint-css.js`, and the browser test, which now asserts rendered content and that nothing runs past the viewport at 320, 768 and 1440px. Puppeteer is pinned through `package.json` and `pnpm-lock.yaml`. The reader's pure functions moved to `reader-core.js`. The third-party README action is pinned to a commit.
- **Consequence**: A broken commit, including an automated data commit, stays off the site until fixed; each deploy takes about a minute longer. A failing or flaky test now blocks the daily data deploy, so a red run needs attention the same day. `browser-test.yml` no longer runs on push by itself: the deploy workflow is its push trigger.

### ADR-027: Ledger Links to Summaries, Design From Titles, Docked List From 900px

- **Context**: Half of the homepage papers (35 of 70) already had a full Thai summary in the reader, but the ledger linked only to PubMed. 489 of 1,461 posts had no study design because older summaries lack the `Study Design:` line. The reader switched to its drawer layout at 1024px, which is the width of a tablet held in landscape. The pages had no share image, `robots.txt` or sitemap.
- **Decision**: `process_blog.js` writes `data/blog/pmids.json`; the homepage adds a `Read the Thai summary` link to each paper found in it. `designOf` falls back to the title, matching only wording that names a design and never guessing "Other". The docked list starts at 900px, and 44px touch targets follow `(pointer: coarse)` instead of the width. Added `assets/og.png`, `robots.txt` (disallowing `/pl/`) and a two-URL `sitemap.xml`.
- **Consequence**: Posts without a design fall to 324. A title-derived design can be wrong where the title mentions a design it does not use; the summary line still wins whenever present. Per-paper pages for search engines were left out: papers remain states of one URL.

### ADR-028: Pure Monochrome Print Replaces Accent Stripes & 4-Color Multi-Accent

- **Context**: The 4-color editorial tokens (`ADR-021`) introduced 2px–3px `border-left`/`border-top` accent stripes, hover `inset 3px` bars, a 3-stop gradient progress bar, and multi-colored tags/badges that read as synthetic "AI card" chrome rather than quiet print typography.
- **Decision**: Retire `--accent-*` and `[data-tone]` from `shared.css`, `index.js`, `blog.js`, `index.css`, and `blog.css` (and remove `CATEGORY_TONES` / `SPECIALTY_TONES`). Return to pure Monochrome Print in Slate (light) and Titanium Navy (dark): `1px solid var(--text-main)` group header rules above open hairline-ruled tool rows (`#works-section`), crisp `1px solid var(--border-strong)` framing on `section-clinical-relevance` and `route-notice`, bold `var(--primary)` + tonal `--bg-paper-list` on the active sidebar row, monochrome chips/badges, and a single `2px` `--primary` reading progress bar.
- **Consequence**: Visual hierarchy comes purely from typography, 1px rules, and surface contrast without category stripes; light/dark theme readability remains WCAG AA/AAA across every token. Amends ADR-021.
